# Direct indexed Maildir implementation

## Query and index selection

Set `[maildir].indexed_sweep = true` in a pilot service instance. The common case is an inbound header census. It contains no text term to look up in Xapian. Use Dovecot's local mailbox metadata and date lookup through a single-purpose helper invoked over the existing SSH connection. Running a separate `doveadm search` followed by one fetch per UID adds a round trip. A single local `doveadm -f tab fetch -u USER storageid mailbox-guid GUID since DATE` per folder supplies the driver IDs. Dovecot chooses its physical query plan. Actual cache and index reuse depends on the mailbox. A full-text word lookup would change the existing raw MIME match contract. [Dovecot fetch](https://doc.dovecot.org/latest/core/man/doveadm-fetch.1.html) and [Maildir dates](https://doc.dovecot.org/main/core/config/mailbox_formats/maildir.html).

The service first applies its existing domain, account and folder rules. The helper reads the v3 UID list header for each distinct folder GUID. Its fixed lookup requests an intentionally wider date window. It enumerates current regular files in the selected cur/new directories, checks filesystem modification times at nanosecond precision, and requires a matching indexed storage ID for every in-window file. The raw reader's interval is lower bound exclusive and upper bound inclusive, using server-local midnight. The filename's delivery date remains the display and sorting key. The guard still costs one directory walk and file stat per entry. Performance must be measured at the outer tool and server.

The helper checks directory and UID-list versions before returning and emits a terminal protocol marker only after all folders succeed. The client validates every path against the requested directory set and verifies the actual selected headers with the existing bounded reader. MIME reads, paging and cache lifetime use the existing implementation. Unreadable headers or a scan cap remain visible. Existing concurrent-delivery limitations across independent mailboxes still apply. Downstream consumers must require clean coverage before checkpointing.

Each SSH probe gets at most one third of the remaining search deadline, capped at 28 seconds. The helper has a 25-second wall-clock alarm and limits matching storage IDs and file paths. Any error, stale/missing index result, unsupported storage ID, timeout, partial protocol or out-of-scope path retries the original raw search for that mailbox. A helper failure never becomes a clean zero. If the raw search also fails the normal partial result survives. `criteria.indexed_mailboxes` reports how many mailbox probes succeeded; subtracting this from scoped mailboxes on a complete, eligible uncached sweep gives the raw count. Cached pages carry the same count.

## Operational setup for a reviewed pilot

The helper is deliberately fixed to the documented /var/vmail Maildir++ layout. Other roots use the existing direct reader. The root-owned program and its parent directory must be unwritable by the SSH and mail service accounts. Install the reviewed `scripts/maildir-index-sweep` as `/usr/local/libexec/maildir-index-sweep`, mode 0755, root ownership. The interpreter runs isolated Python 3. Use a sudoers drop-in checked with visudo. Replace the example login with the existing mail-reader login.

```sudoers
mailreader ALL=(vmail) NOPASSWD: /usr/local/libexec/maildir-index-sweep
```

The rule grants execution of this fixed helper as the mail owner. It accepts a validated mailbox, two dates and a list of scoped Maildir directories. It chooses the command, field names, GUID and flags itself. Granting the client the generic doveadm binary would also expose administrative verbs. The existing raw reader permissions continue to serve fallback. The Dovecot lookup can perform routine internal bookkeeping under its mail user. No administrative index command is part of the lookup. In staging, verify that the mail owner can resolve the single user's settings. If the authentication socket denies lookup, leave the feature off pending a separately reviewed least-privilege service configuration. No Dovecot config change is required on hosts where this lookup already works.

## Index maintenance and client impact

The census uses mailbox metadata. Keep any configured Xapian body index and Dovecot's existing search fallback for normal mail clients. Handle Xapian repair as a separate operator change. Inventory the affected GUID, table owner and permissions, message count, available disk and current backup first. Check access as the mail owner. An age alone is insufficient evidence of staleness. In a quiet overnight window, repair only the confirmed permission problem, then run the version-specific `doveadm fts rescan -u USER` and `doveadm index -u USER MAILBOX` sequence on a restored account first. Rescan may affect other folders in that account. Confirm the installed plugin's behavior before using it on a live user. Select one account at a time, lower CPU and I/O priority, reserve space for both old and rebuilt tables, and stop before the morning collection window. Stop on delivery delays, elevated client latency, low disk or new index errors. Verify indexed search against direct results before the next account. Retain mail files, UID lists, flags and UIDVALIDITY throughout. Client search results and latency can vary during rebuild. Keep a Dovecot 2.4/Flatcurve migration in a separate change.

## Measurement and reversal

1. Use fixed account/folder sets and absolute dates for a normal day, a high-volume day, a large Archive and an empty folder. Include a message delivered at each boundary, a flag rename, a raw-only message and a controlled index permission failure. Use synthetic fixtures for mutations. Run clean caches in separate service processes, then measure hot pages separately.
2. Alternate raw and indexed runs at least ten times per shape. Record server query duration, complete outer tool duration, first and all page p50/p95, number of candidates and hits, indexed count, timeouts, CPU time, I/O wait, peak resident memory and available disk. Keep message contents and account identities out of timing logs. Check delivery latency during the approved pilot.
3. Compare ordered IDs, header fields, counts, membership, warnings and attachments across every page. Require the PRD parity and latency gates. If instability or late deliveries invalidate a comparison, repeat the same frozen window. Never advance a live business checkpoint during benchmarking.
4. To roll back, disable `indexed_sweep` and reload the reader in an approved service window. The previous grep path serves the next uncached query. Remove the helper-specific sudo entry and binary once no instance uses them. The feature creates no new message store. Reverse an operational index repair separately using its pre-change configuration and tested Dovecot recovery procedure.

The release fixture exercised Dovecot 2.3.19.1 with an invented message in Maildir. The helper returned the exact current filename for its delivery window and a clean empty result for a later window. Restricted access to the stats-writer socket produced a diagnostic and correctly rejected the probe. Confirm both user lookup and stats socket behavior for the pilot identity. No production privilege change is implied by the fixture.
